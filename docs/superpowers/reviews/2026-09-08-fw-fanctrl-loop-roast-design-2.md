## Rejected (with reason)
- §2.4/§3.4/fwloop.12 observe_applied input has no validity rule — reject 2/3: Sample already carries gpu_w_valid and the existing controller idiom NaN-gates windows before calib::steady::tail_mean (which refuses to average across an outage), so §2.4's 'the same 5-sample tail-mean the fan window uses' inherits the validity gate; the cited §Facts 'power.limit N/A' concerns the power-limit query, not power draw. Worth a one-line copy-edit naming gpu_w_valid in fwloop.12.
- §2.4/§2.9 RAPL vs commanded-cap scale mismatch caps u = Kc·e/δ — reject 2/3: RAPL package power and PPT VALUE come from the same SMU telemetry and track the commanded limit within a few percent on this hardware class; the existing STICKINESS_MARGIN_W = 5.0 W ('RAPL vs STAPM accounting slack') already encodes the known gap as additive, not multiplicative; the overclock.net quote is about socket-vs-die losses, not RAPL-vs-PPT reading skew. Ground's under-read-direction concern remains a cheap spike (log measured vs commanded under a binding cap) but is not a demonstrated gap.
- §2.6/§2.2 MA reconciliation not gated on active — reject 2/3: the socket's ma_temperature is the designated authority (Decisions line 32) and its frozen-while-paused value is what fw-fanctrl's curve will actually react to on resume, so reseeding toward it is convergence, not corruption; §2.2 says a seed stands in for a full window (no 60 s refill); and the §5 'within 1 °C in steady state' assertion is scoped to steady windows, which §2.3 defines as requiring active: true.
- §3.3/fwloop.13/21 FOPDT denominator 'per axis' vs total delta — reject 3/3: the claimed bias direction is inverted (a smaller CPU-only denominator raises K and lowers Kc), §Facts records that the dGPU never feeds the EC max on this machine so the CPU-axis delta is the physically correct denominator, and the current text is itself the iteration-1 R-fix for the nominal-30 W bias. The per-axis→scalar combination rule could still be spelled out in fwloop.13 as a copy-edit.
- §2.8 NVMe reporting-only justified only from the SoC-idle regime — reject 2/3: §2.8 gives a second, regime-agnostic reason ('airflow at full tilt did not hold it', measured at ~4748 RPM, plus the drive self-throttles), §Facts discloses the confound, and §6 already records what a real lever would need; this restates the R2 tradeoff the prior report confirmed and the spec fixed. Ground's loaded-SoC measurement is a reasonable §6 addition.
