## fw-fanctrl-loop-eb9.3 [task] DeviceLoop core: types, thermal PI, clamps, hold, tick contract
blocking deps: []
Spec §2.3 (rev3) steps 1, 2, 4, 5, 6, 7, 8 and the tick contract — the UNBLOCKING ARTIFACT for every consumer. New control/device_loop.rs: DeviceLoop generic over unit (W | MHz); Gains{kc, ti_s} with the spec's CPU/GPU defaults and a default_gains(ma_interval_s) constructor (θ_eff from the live interval); ThermalMode{Regulate, Bypass}; ActuatorState{Verified, Mismatch, Unverifiable}; Hold{None, Shadow, Clamp(Bound{Floor, Max}), ActuatorMismatch, GroupUnavailable, DrawUnavailable, Bypass}; Selected{Thermal, Shadow, Floor, Max}; DeviceDecision; tick(input) -> (cap, DeviceDecision) with input {t_star, group_c: Option, draw: Option, floor, max, mode, actuator}. Thermal candidate: velocity-form PI at PI_PERIOD_S = 5 on err = t_star - group_c, output clamp [floor, max], directional conditional integration at the clamps (the sat_dir rule moved from gpu_pid.rs); NO band, NO parking, NO 'integrate only when selected' gate — while the device is cool the PI integrates upward at its own rate and saturates at max. Selector cap = min(thermal, shadow), tie -> Shadow. TRACKING IS HOT-ONLY AND ONE-SIDED: on every tick with err < 0, thermal := min(thermal, cap) (integrator state set with it); on ticks with err >= 0 the thermal candidate is never modified by tracking; the shadow is never tracked. Bypass: the thermal candidate reports max and its PI state is untouched. draw None: thermal regulation continues, the shadow holds (no rise/fall), hold DrawUnavailable; after DRAW_UNAVAILABLE_DWELL_S = 60 the shadow is set to max until draw returns. group None: hold the last applied cap (max when none was ever applied) with GroupUnavailable; a group that WAS available this session and stays None for GROUP_UNAVAILABLE_DWELL_S = 60 releases that device to max (cap = max, a normal write) with the GroupLost flag until it reads again (then thermal resumes from max, shadow reseeds); a group None from the first tick is absent, not lost: reports max, no dwell, no flag, caller skips the write. ActuatorMismatch: both candidates frozen (no integration, no shadow move, no tracking) until the first Verified; the applied cap is always min(cap, max) so a lowered max (guard ratchet) takes effect even while frozen. Quantise 0.5 W / slew 105 MHz/s (GPU_RISE_SLEW 300 MHz/s when the shadow is selected and rising; floors and ratchets win) moved from allocator/gpu_pid. The shadow candidate in THIS bead is a stub (shadow = max; Selected never Shadow) — eb9.4 fills it in; the seed/resync API: seed(thermal_at: Option<unit>, shadow_at: Option<unit>) (None = max / deferred) and resync_error() (resets e_prev only; no proportional kick; shadow untouched). Pure, no I/O. The 'first-order plant' in the acceptance is a local test stub in the test module.
Acceptance: step response on a first-order plant within 1 % with <= 5 % overshoot at defaults for both units; clamp hold and directional unwind tests (carry the gpu_pid unwind test over); with the group below T* for 300 ticks and an externally lower cap (stub shadow) the thermal candidate is UNTOUCHED (stays at max); on the first tick with err < 0 thermal == cap and on the next PI tick thermal < cap (hand-over, no windup); Clamp carries its bound; Bypass reports max and preserves PI state across a Bypass/Regulate round trip; draw None keeps regulating and after the dwell the (stub) shadow is max; group None from the first tick reports max with GroupUnavailable and no GroupLost; a group lost after being available releases to max with GroupLost after 60 ticks and regulation resumes on return; Mismatch freezes and a lowered max still lowers the applied cap; after seed(Some(x), _) the first tick applies min(x, shadow) without a kick; after resync_error() the next tick's proportional term is zero; default_gains(20 s) yields a larger Kc than default_gains(60 s).
